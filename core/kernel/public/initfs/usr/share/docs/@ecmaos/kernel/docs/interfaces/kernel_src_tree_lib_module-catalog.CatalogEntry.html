Interface CatalogEntry

The in-tree modules that are not in the boot bundle (zip, iso, dropbox, googledrive): the site serves them with a catalog at /modules/index.json, and the kernel fetches one the first time something asks for it by alias (request_module). The file lands in /lib/modules/RELEASE/kernel/ like any module, so it stays for next time, and the signature on it is checked when it loads, not here: the catalog and the files come from the same place, so they prove nothing about who made the module. Only the hash is checked, to catch a damaged download.
