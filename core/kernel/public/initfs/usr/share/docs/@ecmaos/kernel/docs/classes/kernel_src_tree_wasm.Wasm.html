Class Wasm

Every wasm program (a core module: WALI, wasm32-wasip1, emcc or none of those; a Preview 2 component) runs as a worker process under /bin/wali (see canRunInWorker). What stays here is the work the worker cannot do: compiling a module once for the checks a launch asks, and transpiling a component with jco, which is too large for the worker's bundle.

canRunInWorker

  • canRunInWorker(wasmBytes: Uint8Array): Promise<boolean>

    Whether a module runs as a worker process under /bin/wali: any core module. A WALI module, a WASI one (whatever else an emcc build adds; asyncify is fine) and one with no WASI imports all go; the worker says why a library, or a WASI module with no memory, is not a program. The module is compiled once for all of these checks: a launch asks on every run.
