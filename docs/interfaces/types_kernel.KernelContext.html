Interface KernelContext

The cross-cutting primitives every subsystem may depend on, with no back-reference to the Kernel itself.

A subsystem that needs another subsystem declares a narrow deps interface alongside this (typically a Pick<> of the sibling it actually uses) rather than growing this type. If a field feels like it belongs here, that is the signal it is a real dependency and belongs in deps instead.
