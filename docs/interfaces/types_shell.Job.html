Interface Job

One pipeline the shell is tracking for job control: a | b | c & is a single job with one entry in processes per stage that went through a real @zenfs/linux Process (executeViaExecve's js/node binfmt path) -- a pipeline of ordinary coreutils has no process handle at all, since those run synchronously in the shell's own tick and can't be signaled independently. This is a deliberately simplified single-foreground-job model, not POSIX process groups: @zenfs/linux exposes one thread per Process and no pgid concept, so "the foreground job" is tracked as a single Job reference on Shell rather than real pgid-based terminal control.
