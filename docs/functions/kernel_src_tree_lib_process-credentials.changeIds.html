    What setuid, setreuid and setresuid (and the group calls, which follow the same rules) leave a process's ids as, or undefined when Linux would refuse with EPERM. A caller whose effective user is root may set any id; any other may only set an id to one it already has (real, effective or saved), and setuid then changes only the effective one.

    Parameters

    • current: IdSet
    • privileged: boolean
    • how: "id" | "re" | "res"

      id is setuid(a), re is setreuid(a, b), res is setresuid(a, b, c)

    • b: number = KEEP
    • c: number = KEEP
